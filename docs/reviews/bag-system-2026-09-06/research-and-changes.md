## Backpack Hero에서 확인한 원칙

원작의 공식 소개는 소지 여부뿐 아니라 배치 위치가 아이템 성능을 바꾼다고 설명한다. 공간이 곧 전투 선택의 일부다. UpNext에도 이 원칙을 적용하려면 사용자가 배치를 바꾸기 전에 얻고 잃는 효과를 읽을 수 있어야 한다. [공식 Steam 소개](https://store.steampowered.com/app/1970580/Backpack_Hero/)

개발자의 2024년 12월 공지는 빈 행 공간에 비례하는 방어, 주변 공간을 비워야 켜지는 유물, 인접하거나 대각선에 생성되는 동료처럼 서로 다른 공간 조건을 제시한다. 같은 공지에서 모호한 거리 표현을 수정하고, 보유 장비와 어울리는 보상이 나올 가능성을 높이는 아이템 그룹도 설명한다. 이를 통해 배치 게임에는 조건의 명확성, 여러 선택지, 조합을 완성할 수 있는 획득 경로가 함께 필요하다고 판단했다. [개발자 변경 내역](https://steamcommunity.com/app/1970580/allnews/)

아이템 형상, 효과 범위, 전투 효과, 속성 변경을 별도로 정의하는 구조도 확인했다. 연결선은 실제 조건과 효과에서 파생되어야 한다. 이번 개선에서는 시너지 계산 결과를 상세 설명과 배치 추천이 함께 사용한다. [Backpack Hero 모딩 문서](https://backpack-hero.com/mods/JSON_Reference/Items/)

## UpNext에서의 설계

UpNext는 탐험 진입 때 영웅 상태를 확정하는 자동 전투 게임이다. 원작의 모든 아이템 사용과 자원 소비 방식을 복제하는 대신, 탐험 전에 하는 장착과 지원 배치를 하나의 빌드 선택으로 보여준다.

- 영웅 옆 4개 슬롯에 장착한 장비는 자기 능력치를 제공한다.
- 가방 안의 장비는 연결 조건에 맞을 때 지원 보너스를 제공한다. 보관 중인 장비의 모든 능력치가 더해지는 것은 아니다.
- 정리 대기 아이템은 전투 효과가 없다.
- 장착 교체 시 기존 장비가 가방으로 돌아가며, 그 장비의 지원 효과도 함께 달라진다. 비교에는 이 변화를 포함한다.
- 추천은 선택한 아이템 하나의 합법적인 위치와 회전을 검사한다. 다른 능력치를 낮추지 않으면서 시너지가 증가하는 위치를 제안한다. 검사 중 모든 능력치가 동등 이상이고 하나 이상 더 높은 자리가 나오면 그 자리로 추천을 갱신한다. 전체 가방의 최적해를 보장하는 기능은 아니다.
- 추천은 미리보기 후 명시적으로 적용한다. 다른 아이템은 자동으로 재배치하지 않는다.
- 기존 아이템, 구매한 확장, 강화 수치, 저장 형식과 전투 보너스 계수는 유지한다. 합성용 표시만 제거하며 합성 보상과 비용은 유지한다.

## 읽을 수 있는 빌드 예시

**치명타 중심:** 무기를 장착하고 장신구를 옆에 둔다. 장신구 1개당 치명 확률 보너스 3%p, 최대 2개다. 같은 활동의 장신구라면 해당 장착 장비의 가장 높은 능력치 보너스도 함께 생긴다.

**방어 중심:** 방어구를 장착하고 일반 부적을 옆에 둔다. 1개당 VIT 3, 최대 2개다. VIT는 받는 피해를 줄이는 능력치다.

**사진 지원:** 사진 부적을 여러 장착 슬롯의 상하좌우 또는 대각선에 놓는다. 강화에 따라 각 슬롯의 가장 높은 능력치에 1, 2, 3을 더한다. 슬롯마다 효과가 높은 사진 2장을 적용한다. 효과가 같으면 가방 좌표 순서로 결정한다. 약한 사진을 추가해 기존의 강한 효과가 줄어들지 않는다.

**큰 장비의 공간 선택:** 같은 활동 지원은 접촉한 변 개수가 아니라 가방 장비 전체 크기를 기준으로 계산한다. 1칸 5%, 2칸 10%, 4칸 20%이며 슬롯당 합계 30% 상한이다. 상세 화면에서 크기와 최종 보너스를 함께 확인할 수 있다.

## 추가 코드 및 게임성 리뷰

- **사진 성장의 역효과:** 기존에는 좌표가 빠른 사진부터 2장을 골랐다. 강화 +10 사진과 +5 사진 옆에 +0 사진을 놓으면 총 효과가 +5에서 +3으로 줄 수 있었다. 효과가 높은 2장을 먼저 골라 강화의 가치를 유지한다.
- **추천의 품질:** 사진 하나로 방어구 VIT +1만 얻는 자리를 먼저 발견하면 검색이 끝났다. 이제 같은 VIT +1에 무기 STR +1도 얻는 자리가 있으면 그 자리를 추천한다. 능력치마다 임의의 가중치를 붙이지 않고, 다른 능력치를 희생하는 추천은 하지 않는다.
- **연결 표시의 정확성:** 실제 보너스는 30%에서 멈추는데 연결은 35%까지 표시했다. 이제 실제 적용분만 표시한다. 마지막 아이템의 기여가 일부만 남으면 그 남은 비율을 표시한다. 전투 보너스 계수는 바뀌지 않는다.
- **해제 후 방향:** 가로 무기를 장착했다 해제하면 빈자리에 세로로 돌아올 수 있다. 이때 선택 상태에도 반환된 실제 방향을 반영해, 다음 회전과 드래그가 화면의 아이템 방향에서 시작하도록 했다.
- **최대 강화:** 일반 장비 +20, 사진 부적 +10에서 강화 버튼을 숨긴다. 가방 보관과 장착 중 모두 같은 기준을 적용한다.

시너지 계산과 추천의 기존 오류는 실패하는 테스트로 먼저 재현했다. iOS UI 회귀 테스트는 가로 무기 장착, 세로 반환, 회전, 새 위치 확정 후 실제 타일 모양까지 확인한다.

## 검증 범위

- 웹 전체 자동 테스트: 54개 파일, 947개 테스트 통과.
- iOS: 가방 모델 39개, 실제 스토어 왕복 17개, UI 조작 7개 테스트 통과. 장착·해제, 선택 유지, 해제 후 회전, 상세 열기·닫기, 연결 안내, 영어 최대 확장 가방을 확인했다.
- TS와 Swift 계산 동치: 배치, 시너지, 장착·해제 비교, 추천을 포함한 168개 출력 행 일치.
- 웹 배포용 빌드: `npm run build -- --webpack` 통과. TypeScript와 변경 파일 lint 통과.
- 번역: 4개 언어 × 2,630개 키의 placeholder 검사 통과. iOS 기존 번역 키 삭제 0개, 기존 값 변경 0개.
- Android API 36 에뮬레이터의 Chrome에서 실제 터치 선택, 드래그, 장착, 해제, 상세 화면을 확인했다. Android TWA가 사용하는 동일 웹 컴포넌트를 로컬 테스트 데이터로 실행했다.
- 모바일 웹: 390×844 한국어와 320×568 영어 최대 확장 가방에서 장착·해제 버튼과 상세 화면을 확인했다. 회전 취소는 원래 배치를 보존하고, 위치 확정 때만 방향이 바뀐다.
- 테스트용 웹 진입 페이지는 검증 후 삭제했다. 원격 데이터나 출시 버전을 바꾸는 배포는 하지 않았다.

테스트 중 iOS 기존 가방 스토어 테스트에서 Swift의 MainActor 해제 경로가 종료되는 문제가 재현됐다. 리포지토리의 `UpHeroInventoryTests`와 같은 공유 테스트 인스턴스 방식으로 정리했으며, 매 테스트의 상태 초기화와 원래 단언은 유지했다. 이후 스토어 테스트 전부 통과했다.

### 다음 사용자 확인

재미와 이해도 개선은 아직 사용자 재테스트가 필요하다. 다음 피드백에서는 설명 없이 첫 연결을 만들 수 있는지, 교체로 잃는 효과를 예측하는지, 장착·해제·회전 취소가 의도대로 느껴지는지를 확인한다. 이번 구현은 배치 조건과 결과를 읽고 직접 조합을 바꾸는 데 집중했다. 드롭 확률이나 장비 성장 계수를 바꿔 재미가 개선됐다고 주장하지 않는다.
