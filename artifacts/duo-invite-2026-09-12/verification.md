2인 불꽃 초대 수정, 2026-09-12

참여 전에 비공개 `duos/{id}` 문서를 읽는 기존 트랜잭션은 두 사용자 모두 로그인해도 거부됐다. 배포 중인 Firestore 규칙을 내려받아, 서로 다른 두 인증 사용자로 에뮬레이터에서 `permission-denied`를 재현했다.

웹과 iOS 모두 초대 문서만 읽고, 본인 멤버 정보 추가와 초대 사용 처리를 같은 트랜잭션으로 기록하도록 수정했다. 규칙은 초대의 대상, 생성자, 만료, 사용 상태와 두 문서의 변경을 함께 검사한다. 기존 멤버만 불꽃 데이터를 읽을 수 있는 제한은 유지된다.

공유 주소는 `https://up-next-phi.vercel.app/i/{code}`다. 설치된 앱은 참여 화면으로 연결하고, 웹에서는 앱 열기와 스토어 설치 안내를 제공한다. 로그인 또는 재실행 중에도 받은 초대를 보관한다. 설치 직후 초대 자동 복원은 제공하지 않으며, 안내대로 같은 링크를 다시 열어 참여한다. 기존 6자리 코드 참여도 유지된다.

검증 결과:

- TypeScript 테스트 44개 통과. 초대 저장, 새 링크 우선 처리, WebView 재로드 시 이전 시작 링크로 되돌아가는 문제도 검증했다.
- Firestore 에뮬레이터에서 정상 참여, 동시 참여 1명 제한, 만료·재사용·자기 초대·위조 거부, 비멤버 읽기·초대 열거·타인 체크인 변경 거부, 나가기 후 접근 차단 확인.
- iOS 단위 테스트 3개와 UI 테스트 1개 통과. 실제 URL 열기, 재실행 복원, 닫기, 잘못된 코드 거부 확인.
- Android 디버그 APK 빌드와 설치 성공. 링크를 통한 앱 시작, 강제 종료 후 런처 재실행, 초대 복원, 로그인 화면 진입 확인. 실행 중 새 링크 수신과 나중에 선택 시 초대 삭제도 실제 앱에서 확인했다.
- 웹 프로덕션 빌드, 변경 파일 ESLint, 4개 언어 번역 키 검사, 카피 검사 통과.
- 웹 초대 화면, 로그인 진입, 잘못된 주소의 404, Referrer-Policy, AASA JSON 응답 확인.
- iOS와 Android 화면 캡처를 직접 확인했다. iOS 제목 색상과 접근성 식별자 전파 문제를 수정한 뒤 UI 테스트를 통과했다.

Android 검증용 APK만 localhost 개발 서버를 사용했다. 제품 설정은 기존 HTTPS 주소를 유지한다. iOS 검증은 HEAD와 이번 변경만 복사한 별도 디렉터리에서 수행해, 공유 체크아웃의 진행 중인 오디오 변경을 섞지 않았다.

현재 상태는 로컬 구현 및 검증 완료다. 이번 변경의 커밋, 푸시, 서버 배포, App Store 제출은 아직 하지 않았다.

실제 반영 시 필요한 작업:

- Firestore 규칙과 웹을 함께 배포한다. 확인 시점의 로컬 `firestore.rules`에는 운영 규칙에 없던 별도 `feedback` 구간도 있으므로, 2인 불꽃 규칙 변경만 운영본에 반영하거나 해당 구간을 별도로 검토한다. Firebase 대상은 `upnext-6ca93`다.
- 웹의 `/i/{code}`와 `/.well-known/apple-app-site-association`을 운영 HTTPS 주소에서 확인한다.
- iOS Associated Domains 권한을 포함한 새 빌드를 배포한다. 운영 도메인과 실제 설치 앱 간의 Universal Links 연결은 이 배포 후 확인해야 한다. 로컬 UI 테스트는 `upnext://invite/{code}` 시스템 URL 진입을 검증했다.
- Android 기존 앱에 App Links, App, Share 플러그인이 포함되어 있다. 운영 웹 배포 후 Play 서명 앱에서 HTTPS 링크를 재확인한다. 스토어 공개 설치 가능 여부는 이번 검증 범위에 포함하지 않았다.

규칙 테스트 재실행: Java 21 이상과 Firebase CLI가 설치된 환경에서 `npm run test:duo-rules`. 테스트용 프로젝트 ID는 `demo-upnext-duo`다. 이미 8188 포트의 테스트 에뮬레이터가 실행 중이면 `node scripts/duo-rules.test.mjs`로 실행한다.
