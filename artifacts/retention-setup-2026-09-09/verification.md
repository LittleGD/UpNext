# 알림·위젯 설정 플로우 검증

2026-09-09. 최신 main의 가방·룬 상자·경험치 수정 위에 기존 미커밋 사운드 작업과 리텐션 튜토리얼을 통합했다. iOS 1.3.0 빌드 31, Android 2.0.2 코드 6이다.

첫 개인 챌린지 완료 후 알림 시간을 선택하고 실제 권한·예약 확인까지 진행한다. 두 번째 완료 후 위젯 추가를 연습한다. 같은 기기에서는 각 안내를 한 번만 자동 표시하며, 설정에서 다시 열 수 있다. Android에서는 런처의 위젯 고정 요청을 사용하고, iOS에서는 실제 홈 화면 조작을 안내한다. 두 플랫폼 모두 설치 여부를 조회한 뒤 완료를 표시한다.

## 자동 검증

- 웹: 66개 파일, 1,019개 테스트 통과.
- iOS: 단위 테스트 449개와 UI 테스트 6개 통과. 알림 권한 거절 후 기기 설정에서 복구, 첫·두 번째 완료, 건너뛰기, 영어·동작 줄이기, 실제 홈 위젯 설치, 카드매치 보상 확인을 포함한다.
- 웹·Swift 규칙 비교: 13개 스위트, 1,665줄 일치.
- 오디오: 63개 효과음과 10개 음악의 실제 디코딩, 반복과 화면 전환, 음소거를 확인했다. 브라우저 검사 오류 0건.
- 최종 빌드 31의 픽셀 아이콘 적용 후 리텐션 UI 테스트 5개를 재실행했다. 모두 통과했다. 아이콘 및 음원 무결성 검사도 통과했다.
- 4개 언어 카탈로그 검사 통과. 기존 Localizable.xcstrings를 변경하지 않고 별도 RetentionSetup 테이블을 추가했다.

## Android API 36 에뮬레이터

1. 실제 챌린지 완료 함수로 첫 안내를 발생시킨 뒤 20:00을 선택했다.
2. 시스템 알림 권한을 거절하고, 안내의 설정 버튼으로 UpNext 알림 설정을 열었다.
3. 알림을 켜고 복귀했다. 네이티브 NOTIFICATION_STORE의 ID 1001이 20:00으로 예약된 것을 확인했다.
4. 두 번째 챌린지 완료 후 길게 누르기와 크기 선택을 실행했다.
5. 시스템 위젯 추가를 취소했다. 설치되지 않은 상태에서 완료로 처리되지 않는 것을 확인했다.
6. 다시 추가하여 홈 화면에서 실제 2/2 완료 데이터를 확인했다. 위젯을 눌러 앱으로 돌아온 뒤 설치 확인 화면을 검증했다.

검사 중 기존 Capacitor 프록시를 async 함수의 반환값으로 전달하면 존재하지 않는 native `then` 메서드를 호출하는 문제를 재현했다. 알림과 위젯 브리지를 직접 호출하도록 수정했으며 회귀 테스트를 추가했다.

Android 테스트용 임시 페이지와 로컬 서버 주소는 배포 소스에서 제거했다. 구형 Android 셸은 새 브리지 기능이 없으면 안내를 자동으로 숨긴다. 새 네이티브 기능은 코드 6 패키지에 포함되어 있다.
